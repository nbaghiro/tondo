# Builder review, 2026-10-31

Three separate read-only reviews of commit b0a2384: a first-time user walkthrough against a Neon stand-in, an adversarial code review, and an audit against the plans. No injection or authorisation hole was found. Findings below are grouped by priority.

## 1. Fix now: visibly broken

Done on 2026-11-01.

- Icons render about 220px wide in most section panels, because nothing styles `.icon` (`apps/editor/src/components/Icon.tsx`).
- "Publish without these" offers to publish, then shows blocking items. Warnings run before the server's checks.
- Publish problems don't name the section or item, and the list disappears after each click.
- The phone layout scrolls 56px after adding Shop, hiding the top bar.
- A new list section focuses its title field, which scrolls the panel past its styles and items.
- The Back button covers the logo in the start flow.
- Long names overflow signature headers such as Bakehouse and Ticket.
- Empty tabs show on the live page.

## 2. Fix now: trust and honesty on live pages

Done on 2026-11-01. Untouched sample words stay out of live pages and are listed before publishing. Items with no link draw as plain text. Download shows as coming, like the other held sections. To-do dots remain a separate list from the publish checks.

- Untouched sample text and prices publish as real content, including invented reviews.
- `services`, `events`, `team`, `posts` and `file` publish dead links.
- Download can be added, but uploads nothing and always links to `#`. Mark it Soon.
- Recolouring rewrites user text and links in `layout: "look"` headers (`packages/render/src/header.ts:96`, `style.ts:273`).
- A quoted URL in a text block links to the wrong address (`packages/page/src/blocks/text.ts:6`).
- `GET /api/v1/pages/:handle` exposes hidden and scheduled blocks, and nothing uses it (`apps/server/src/app.ts:68`).

## 3. Fix before any real users

Built on 2026-11-01. What needs real infrastructure to confirm is listed in `deploy.md`.

- Lost save response can lose work: a retry gets a 409, and Reload ignores the backup (`saver.ts`, `storage.ts`, `db/src/pages.ts:42`).
- One unreadable block takes down a live page and its editor (`upgrade.ts`).
- A Neon outage looks like being logged out (`apps/server/src/auth.ts:60`).
- No rate limits or body limits on auth, publish or uploads, and each page view renders and writes uncached.
- Handles like `tondo`, `security`, `billing` and `status` are claimable (`packages/page/src/handle.ts`).
- No unpublish, account deletion, address change, abuse report or phishing check.
- Page time zones are missing: event times are treated as UTC.
- The live panel has no address or copy link, and pages have no share preview tags.

## 4. Before launch: needs Naib or real infrastructure

- Render, R2, production Neon verification, own Google client and email sender.
- A real password reset, Google to completion, iPhone Safari, Android, Mac Safari, Firefox and screen readers.
- Legal and support pages, real prices, and marketing claims about unbuilt features (`Pricing.astro`, `Teams.astro`).
- Staging pass on Render: scheme behind the proxy and client IP forwarding to Neon are unverified.

## 5. Soon after

- Sign-ups, forms and contacts, then file delivery, a stats view, booking embeds, rich link previews, RSS.
- Accessibility: focus in the editor canvas, skip links, `<main>`, icon names, image alt text, radio arrow keys.
- Weight: `/` loads 5.96 MB of images, uploads have one size, no compression or immutable caching from the server, and Google Fonts on published pages conflicts with the no-tracking plan.
- Security headers on `/app`, sandboxed canvas iframes, startup failure when `DATABASE_URL` is missing in production.
- Copy: "shelf" and "blocks" in tabs, "Soft" twice under Buttons, status copy as a button label. One list for to-do dots, warnings and blockers.
- Stale docs: `deploy.md`, `README.md`, `features.md`, `block-system.md`, `how-it-works.md`, `roadmap.md`, `builder-port.md`, `cleanup-log.md`.
- Weak or missing tests: undo test that never presses undo, held layouts counted as reached, overflow in 5 of 50 looks, no tests for `saver.ts`, reset, malformed drafts, touch drag, WebKit or Firefox.

## Re-walk after the fixes

A fresh review of 1994584 found a new live-page crash and problems with the first sample-content rule. Fixed after that:

- One surviving tab draws as its blocks, and a block that can't be drawn is skipped and logged, so content can't return a 500.
- Sample content is now compared field by field in `packages/page/src/sample-content.ts`. A person's own field always stays, a sample field is empty on the live page, and one table says which rows need what.
- Publish lists recompute from the draft, every issue opens and scrolls to the exact field, and a page with only its top can publish.
- Ordinary names don't break mid-word in any look, a second media link no longer replaces the first, and logo tiles fit on phones.
- Sections that won't show say "Not going live yet" in the list.
